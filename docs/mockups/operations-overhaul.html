    For the owner — react to specifics

    What changed & why — 9 decisions in this proposal
    1. Global search becomes the header's centerpiece. The workspace spans 18 tabs, yet search today is a small corner box. The proposal gives it a wide, always-ready field with a / keyboard shortcut and grouped results — clients, cases, bookings, suppliers, documents — that jump straight to the record. On phones it becomes a full-width row directly under the brand.
    2. Today is now a cockpit, not a report. The five queues that decide the day — payments due (+7d), departures (+30d), unconfirmed supplier bookings, overdue follow-ups, documents pending review — each get a card with a live count, and every row carries its own Open action. Completing a follow-up happens inside the card; the count drops without leaving the screen.
    3. The case command center leads with the next action. A labelled amber hero (action + reason + Open) sits top-left; blockers and the next deadline ride the right rail, and an overdue deadline gets a red state visible from across the desk. The current page states these as prose fields scattered across cards — here they are the first screenful, and the record chain INQUIRY → QUOTATION → BOOKING → DEPARTURE is stamped across the header.
    4. Switching cases is a selector, not a navigation. The current workspace makes you tab out to Inquiries to pick a case. The proposal keeps the case open in one place and swaps its contents — next action, blockers, finance, travelers, suppliers, tasks — so comparing two cases is two clicks in the same chair.
    5. Money is displayed as math, never just as numbers. Booking & payments shows an explicit statement of account: billed → verified → allocated → outstanding, with pending-verification funds kept visibly outside the total until a human verifies them — the same rule the server enforces. The collection bar fills only with verified money.
    6. Readiness is honest pills. Every member × check (BOOKING_PAID, TICKETING, VOUCHERS, DOCUMENTS) reads PASS / FAIL / UNKNOWN, with UNKNOWN drawn as a dashed pill because "no requirement record" is a different fact than "failed" — and each FAIL points to the task it raised.
    7. The quotation view shows the client's eyes. The working copy — selectable option cards with one clear SELECTED state, an items table, validity — sits beside a print-styled preview of the exact sheet the client receives, so staff never guess how a quote reads on the other end. Switching options updates both sides instantly.
    8. One product family with the Expo Console. Identical tokens — navy authority band, manifest-green primaries, passage-blue data accents, chart-paper ground, stamped pills, 20–27px tabular figures — so the two consoles read as one system. Even the demo data overlaps: Grace Lim's BOOKING-2026-000187, captured at the September expo, appears here in Today and in the Seoul departure. The Events tab in the navigation opens that console in a new browser tab — the same separation production uses, so each console keeps its own URL and history.
    9. Quotations are built, not just displayed. Staff spend most of their day assembling quotes by hand, yet the old view only showed the finished product. The new builder starts from the inquiry itself (here: Roberto Aguilar · Ho Chi Minh City · 2 adults), adds items line by line with the supplier cost kept muted and internal, attaches flights and itinerary days, and recomputes subtotal, service fee, grand total and margin on every add, remove and fee change — while the client sheet on the right redraws live, so what the client receives is never a guess. Cost, supplier notes and margin never reach the client side. Every added line, flight and day is editable in place — pencil, revise, save — and the Quotations view's Edit quotation button reopens the builder loaded with the selected option, so fixing a sent draft starts where the work left off.

    Mockup for evaluation only — tab switching and the marked demo interactions (global search, case switching, option switching, building a quotation item by item, verifying a payment, completing follow-ups) run locally in the browser; there are no server calls and nothing is saved. Feature set mirrors the live Operations Workspace (Today overview, case command center with next-action projection, quotations with option cards and client preview, a manual quotation builder whose client sheet updates live as items, flights and days are added, obligations/payments with verification states, departure readiness checks, document review queue, privacy overview); the other tabs would keep their current design in this proposal. The Events tab opens the sibling Expo Console proposal (expo-console-overhaul.html) in a new tab — a local file, still no network.
